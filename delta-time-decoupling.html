Delta time: why movement should ignore FPS

A fast computer draws more pictures per second. The game world should still move at the same speed. This page shows the bug, then the fix, with moving ships you can scrub.

One sentence: Frames are how often you redraw. Seconds are how the game should think about speed. dt (delta time) is the bridge: “how many seconds passed since the last frame?”

1. Two different speeds (do not mix them up)

  • Drawing speed (FPS) = how many times per second your computer paints a new picture.
  • World speed = how fast the ship should move in the game, in real seconds (example: 300 pixels per second).

Decoupling means: world speed is written in seconds. Drawing speed can be anything. They stay separate.

2. The bug: move “per frame”

Bad code says: every time I draw, nudge the ship 5 pixels. Then a machine that draws more often moves the ship farther in the same real second.

Machine FPS Move each frame Distance in 1 second
Old laptop 30 5 px 150 px/s
Gaming PC 144 5 px 720 px/s

Same game. Same “5”. Totally different feel. Unfair and broken.

4. The fix: move “per second,” multiply by dt

Delta time (dt) = seconds that passed since the last frame. At 60 FPS, dt is about 1/60 ≈ 0.0167 seconds. At 30 FPS, dt is about 0.033 seconds (bigger gap between frames).

new_x = old_x + (speed_pixels_per_second × dt)

Example: speed = 300 px/s

  • Slow frame: dt = 1/30 → move 300 × (1/30) = 10 px that frame
  • Fast frame: dt = 1/144 → move 300 × (1/144) ≈ 2.08 px that frame

Over one real second, both add up to about 300 pixels. Tiny steps more often, or bigger steps less often. Same trip. 

# Broken (tied to frames)
ship.x += 5

# Fixed (tied to real time)
ship.x += 300 * dt   # 300 pixels per second

6. Tiny glossary

  • Frame = one drawn picture of the game.
  • FPS = frames per second (how often you draw).
  • dt / delta time = seconds between this frame and the last one.
  • Coupled = movement depends on how often you draw (bad for speed).
  • Decoupled = movement depends on real time via dt (what you want).

7. Pygame mental model

Your loop still runs “once per frame.” That is fine. Inside the loop, ask the clock how much time passed, then move using that number. 

clock = pygame.time.Clock()
speed = 300  # pixels per second

while running:
    dt = clock.tick(60) / 1000  # milliseconds → seconds
    # now move with: position += speed * dt

clock.tick(60) both caps how fast you try to loop and returns how many milliseconds the last frame took. Divide by 1000 so dt is in seconds.
